# Персональный помощник «от текста до действия»

Сервис превращает неструктурированный рабочий текст в список конкретных действий: задачи, сроки, ответственные, приоритеты и причины ручной проверки.

Проект демонстрирует полный цикл:

```text
веб-панель → API → база данных → ИИ-операция со строгим JSON → контроль качества → ручная проверка → аудит → экспорт
```

## Возможности

- создание исходного текста через API;
- витрина всех записей;
- ИИ-анализ текста в строгий JSON;
- проверка структуры ответа ИИ;
- автоматическая отметка `needs_review=true`;
- экран записей, требующих проверки;
- карточка записи с исходным текстом, результатом ИИ, задачами и аудитом;
- экспорт данных в JSON и CSV;
- хранение данных в SQLite;
- аудит ключевых действий в `audit_runs`.

## Стек

- Python
- FastAPI
- SQLite
- SQLAlchemy
- Pydantic
- Jinja2
- OpenAI API
- Docker

## Быстрый запуск

Ожидаемое время запуска: до 10 минут.

Проект можно запустить двумя способами:

1. без Docker — через Python и виртуальное окружение;
2. через Docker — одной командой `docker compose up --build`.

Для работы ИИ-операции нужен API-ключ OpenAI.

## Переменные окружения


Для работы ИИ-операции нужен файл `.env` в корне проекта.


Создайте файл `.env` и перенесите в него настройки из `.env.example`, заменив `your_api_key_here` на реальный API-ключ:

Файл `.env` содержит секреты и не должен попадать в репозиторий.

# Запуск без Docker

Требования: Python 3.11+ и `pip`.

## 1. Создать `.env`

В корне проекта создайте файл `.env`:

```env
OPENAI_API_KEY=ваш_реальный_api_ключ
OPENAI_MODEL=gpt-4.1-mini
```

## 2. Создать и активировать виртуальное окружение

Windows PowerShell:

```bash
python -m venv venv
venv\Scripts\activate
```

После активации в терминале должно появиться:

```text
(venv)
```

## 3. Установить зависимости

```bash
pip install -r requirements.txt
```

## 4. Запустить сервер

```bash
uvicorn app.main:app --reload
```

Если запуск прошёл успешно, в терминале появится строка вида:

```text
Uvicorn running on http://127.0.0.1:8000

```

## 5. Примеры API-запросов

Создать входящую запись:

```bash
curl -X POST "http://127.0.0.1:8000/ui/texts" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "source_text=Коммерческий отдел: Марина Петрова, подготовь коммерческое предложение для клиента Альфа до 30.05.2026."
## 5. Открыть проект в браузере

Веб-панель:

```text
http://127.0.0.1:8000/ui/texts
```

API-документация:

```text
http://127.0.0.1:8000/docs
```

# Запуск через Docker

Требования: Docker Desktop.

В этом варианте локальное виртуальное окружение `venv` создавать не нужно. Docker сам установит зависимости внутри контейнера.

## 1. Создать `.env`

В корне проекта создайте файл `.env`:

```env
OPENAI_API_KEY=ваш_реальный_api_ключ
OPENAI_MODEL=gpt-4.1-mini
```

## 2. Собрать и запустить контейнер

```bash
docker compose up --build
```

После запуска откройте веб-панель:

```text
http://127.0.0.1:8000/ui/texts
```

API-документация:

```text
http://127.0.0.1:8000/docs
```

## 3. Остановить контейнер

```bash
docker compose down
```

# База данных

Проект использует SQLite.

База создаётся автоматически при запуске приложения в папке:

```text
data/app.db
```

База данных не добавляется в репозиторий.

Основные таблицы:

```text
input_texts
action_items
ai_results
audit_runs
```

## Что хранится в таблицах

`input_texts` — исходные тексты, статусы обработки, признак ручной проверки.

`action_items` — задачи, извлечённые из текста.

`ai_results` — результат ИИ-операции, сырой JSON, confidence, needs_review и review_reason.

`audit_runs` — журнал ключевых действий: создание записи, запуск ИИ-анализа, ошибки, статус выполнения и длительность операции.

# Как воспроизвести ручную проверку

Для проверки ручной проверки используйте текст:

```text
Марина, подготовь КП до пятницы. Игорь проверь договор.
```

Почему этот текст приводит к ручной проверке:

- срок “до пятницы” является относительным;
- система не должна автоматически превращать относительный срок в точную дату без подтверждения пользователя.

## Шаги

1. Открыть API-документацию:

```text
http://127.0.0.1:8000/docs
```

2. Создать запись через:

```text
POST /texts
```

Тело запроса:

```json
{
  "source_text": "Марина, подготовь КП до пятницы. Игорь проверь договор."
}
```

3. Запустить анализ для созданной записи:

```text
POST /texts/1/analyze
```

Если созданная запись получила другой `id`, используйте его вместо `1`.

4. Открыть витрину:

```text
http://127.0.0.1:8000/ui/texts
```

5. Проверить, что запись получила статус:

```text
Требует проверки
```

6. Открыть экран ручной проверки:

```text
http://127.0.0.1:8000/ui/review
```

7. Открыть карточку записи:

```text
http://127.0.0.1:8000/ui/texts/1
```

В карточке должны быть видны:

- исходный текст;
- результат ИИ;
- причина ручной проверки;
- извлечённые задачи;
- audit_runs.

# Тестовые данные

Тестовые входы находятся в папке:

```text
tests_data/inputs.jsonl
```

Файл содержит 10 тестовых текстов, включая случаи, которые должны приводить к:

```text
needs_review=true
```

Примеры таких случаев:

- относительный срок: “до пятницы”;
- срок “завтра”;
- отсутствие ответственного;
- неконкретная формулировка “когда-нибудь”.
